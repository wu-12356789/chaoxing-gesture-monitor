# iPhone 远程使用

服务端使用 Python 持续轮询。iPhone Safari 负责登录、编辑候选、开始和停止监测，以及查看运行记录。预设轨迹为 `1235789`、`14789`。

## 部署信息

需要提供服务器地址、SSH 用户名、SSH 端口，以及准备用于 HTTPS 的域名。SSH 密钥保存在本机，使用已有 SSH 配置或本地密钥路径即可。域名解析到服务器。部署前检查主机已有站点和端口占用，复用已有 HTTPS 反向代理也可以。

## Docker Compose

将 `src/`、`config.json`、`requirements.txt`、`Dockerfile`、`compose.yaml` 和 `Caddyfile` 放入服务器上的独立目录。服务器需有 Docker 和 Compose。

在该目录的 `.env` 写入实际域名，例如 `SIGN_DOMAIN=sign.example.com`。允许外部访问 80、443 端口。执行：

```sh
docker compose up -d --build
docker compose logs --tail=50
```

只有 Caddy 对外提供服务，Python 应用通过内部网络访问。Caddy 申请 HTTPS 证书。已有反向代理的主机可调整端口与代理配置，避免与既有站点冲突。`--behind-proxy` 仅用于应用确实位于一层可信反向代理后的情况。

首次启动后，访问密钥生成于 `data/work/panel-key.txt`。部署者通过安全终端读取，填入 iPhone 网页的访问密钥输入框。不要把该文件打包进源码或贴入公开日志。

代理模式下，Waitress 只接受 `SIGN_PROXY_PEER` 指定的直接上游传来的 `X-Forwarded-Proto`。仓库自带的 Compose 使用 Caddy 服务名 `proxy`。如使用宿主机上的 Caddy 和仅绑定在宿主机回环地址的 Docker 映射端口，请将应用容器的 `SIGN_PROXY_PEER` 环境变量设为该容器实际看到的宿主机网关 IP。更换代理 IP 后需重启应用，使地址重新生效。

## 使用顺序

1. iPhone Safari 打开部署后的 HTTPS 地址，输入面板访问密钥。
2. 登录学习通。密码仅用于当前登录，不保存到服务器文件。
3. 确认两条手势和检测间隔，点击「开始监测」。
4. 可关闭网页或锁屏。服务器进程继续运行。

Safari 分享菜单可将网页添加到主屏幕。面板密钥保存在当前浏览会话中，重新打开可能需要重新输入。

「断开面板连接」只退出网页连接。「停止」会让后台在当前网络请求返回后停止。服务器重启后，需要再次登录学习通并开始监测。学习通会话失效也需要重新登录。

配置和签到去重记录持久化于 `data/`。更新前保留该目录。应用只支持单实例运行，以免重复轮询。

## 本地检查

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe src/web.py
```

本机访问 `http://127.0.0.1:8765`，访问密钥位于 `work/panel-key.txt`。远程登录学习通须使用 HTTPS。
